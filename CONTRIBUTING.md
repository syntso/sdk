# Contributing

## Branches

- `main` holds released code only.
- `dev` is where work comes together. Branch from it, and open pull requests into it.

Pull requests into `dev` are squash-merged, so the pull request title becomes the commit.

## Commits

[Conventional Commits](https://www.conventionalcommits.org), one line, no body: `feat(sdk): add a typed helper for k8s.apply`. The whole line is at most 72 characters. `git config core.hooksPath .githooks` turns on the local check.

## The interface

`wit/synt-extension.wit` is the contract between the core and every extension, and the core links extensions against the same interface. It follows semantic versioning: additions make `1.1`, `1.2` and so on, nothing is removed or changed within `1.x`, and a change that breaks extensions is `2.0.0`. A change to it is made together with the core.

`schema/extension.schema.json` is generated by the core from its manifest types. Change those in the core, not the file here.

## Code

- One main type per file, named after the type; a concept with more than one file gets a folder, and its main type lives in the file beside the folder. No `mod.rs`.
- `lib.rs` only lists modules and re-exports.
- Errors are `Error` in `error.rs`. No `unwrap()` or `expect()` outside tests.
- No `unsafe`, and no comments or doc comments: names and small functions carry the meaning.
- A new dependency needs a reason in the pull request, and a permissive license (`cargo deny check`).

## Before you push

```bash
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test
cargo clippy --manifest-path examples/hello/Cargo.toml --target wasm32-wasip2 -- -D warnings
cargo build --manifest-path examples/hello/Cargo.toml --target wasm32-wasip2 --release
```

CI runs the tests on macOS, Windows and Linux, builds the example for `wasm32-wasip2`, and runs `cargo deny check`.
